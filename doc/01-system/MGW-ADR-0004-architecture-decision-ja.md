# MGW-ADR-0004 PWA の更新と起動の復旧

## 状況

仕様書は、vite-plugin-pwa で全静的ファイルをキャッシュし、完全オフラインで動くこと（§10、§23、§25）を求めている。また、8 秒以上起動しないときに復旧の画面（`boot.js`）を出すことを求めている（§23）。
新しい版を公開したとき、端末でいつ切り替えるかを決める必要がある。

## 選択肢

1. 新しい版が届いたら「更新」ボタンを出し、押したときだけ切り替える（`registerType: 'prompt'`）。
2. 次に開いたとき、自動で切り替える（`registerType: 'autoUpdate'`）。

## 決定

選択肢 1（オーナーの決定、2026-10-26）。

- 新しい版の Service Worker は待機させる。アプリは「更新」ボタンを出す。押すと切り替えて再読み込みする。
- プレイ中（`playing`）には切り替えない。ボタンを出すのはタイトル画面とランキング画面だけにする（出す場所は 03 で決める）。
- `boot.js` は `public/` に置く普通のスクリプトで、アプリ本体より先に読み込む。
  - 起動のときに 8 秒のタイマーを始める。アプリが起動を知らせたら（たとえば `window.__mgwBooted()` を呼ぶ）止める。
  - 8 秒たっても知らせがなければ、復旧の画面を出す。画面には「再読み込み」と「キャッシュを消して再読み込み」を置く。後者は Service Worker の登録とキャッシュを消す。localStorage（ランキング）は消さない。
- キャッシュするのは build した全ファイル（HTML・JS・CSS・アイコン・マニフェスト）。外部のものはない。

## 理由

- 遊んでいる途中で版が変わらない。
- 手動テストで「更新を押してから確かめる」と手順をはっきり書ける。
- 古いキャッシュで起動できなくなっても、端末の操作なしで直せる。

## 影響

- 手動テストの手順には、「公開 URL を開き、『更新』が出たら押す」を入れる。
- 復旧の画面の文言と見た目は 03 で決める。
