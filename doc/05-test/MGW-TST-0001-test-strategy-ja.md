# MGW-TST-0001 テストの進め方

## 1. テストの種類

| 種類 | 道具 | 何を確かめるか | どこで動かすか |
| :--- | :--- | :--- | :--- |
| 単体 | Vitest | core のルール・物理・得点・音の計画、storage、layout の計算、render の色と絵の大きさ、層の決まり（ESLint） | 手元・CI（`npm run verify`） |
| E2E | Playwright | 画面の切り替え、操作（キー・マウス・タッチ）、大きさ、保存、PWA・起動の復旧 | 手元・CI（`npm run test:e2e`） |
| dist の検査 | `scripts/check-dist.mjs` | 外部の URL がない、マニフェスト、Service Worker、音のファイルがない | 手元・CI（`npm run verify`） |
| 手動 | 実機・目と耳 | 見た目、音色、指で隠れないか、ホーム画面のアプリ、60 fps、公開 | WS の終わり（公開 URL）・リリース |

### 1.1 E2E の端末（MGW-TD-0007 §7）

| project | 端末 |
| :--- | :--- |
| `pc-chromium` | Desktop Chrome 1280 × 800 |
| `iphone11-webkit` | iPhone 11（タッチ） |
| `iphonese-webkit` | iPhone SE（はみ出さないこと） |

- テストは、それぞれ合う project だけで動かす（タッチのテストは iPhone、キーのテストは PC）。
- Canvas の中は読めないので、body の data 属性と `?debug=1` の `window.__mgw`（MGW-TD-0004 §6）で状態を読み・作る。
- 文字の幅や、Canvas の画素の色に頼るテストは書かない（CI と手元でフォントが違うため）。
- 時間のかかるもの（2 秒の待ち、8 秒の起動の復旧など）は、`__mgw.advance` や Playwright の `page.clock` で進める。

## 2. 番号の決まり

- test-case の番号は user-story と同じ（MGW-TC-0001 は MGW-US-0001 を確かめる）。非機能は最後の 0030・0031。
- 確認 ID は `MGW-TC-<4 桁>-<2 桁>`。受け入れ条件 1 つに確かめ方が 2 つあるとき（単体と手動など）は、確認 ID を 2 つにする。
- user-story を足したら、test-case も同じ番号で足す。確認 ID の欠番は使い直さない。

## 3. テストの名前

自動のテストは、名前の先頭に確認 ID を書く。1 つのテストで確認 ID を 1 つ確かめる。

```typescript
test('MGW-TC-0011-02 発射前のミサイルの先端に隕石が触れるとミスになる', () => { … });
```

`npm run check:docs` が、次を確かめる。

- テストに書いた確認 ID が test-case にある。
- test-case の自動の確認 ID が、書いたファイルにある（ファイルがまだなければ「未実装」として数える）。
- 手動の確認 ID が、その test-case を扱う attested-computation にある。
- リリースのときは `npm run check:docs -- --strict` で、未実装・未記録も 0 にする。

### 6.1 確認できないこと

| こと | 理由 | 扱い |
| :--- | :--- | :--- |
| Android の端末（Chrome） | 実機がない | 各 attested-computation の「確認できなかったこと」に書く。E2E の Chromium で、画面と操作の一部だけ代わりに確かめる |
| iPhone 11 以外の iPhone の実機 | 実機がない | iPhone SE の大きさは E2E（WebKit）で確かめる |
| 本当に新しい版を公開したときの更新（E2E） | E2E では版を 2 つ用意しにくい | E2E は `__mgw.simulateUpdate()` で表示と操作を確かめ、実際の更新は WS の終わりに公開 URL で手動で確かめる |

## 7. 手動テストの進め方

1. Claude Code が、公開 URL・「更新」を押すこと・端末ごとの確認項目（§6 の確認 ID）を案内する。
2. オーナーが iPhone 11 と PC で確かめ、結果（OK、または NG の項目と様子・スクリーンショット）を返す。
3. Claude Code が attested-computation に結果と「確認できなかったこと」を書く。
