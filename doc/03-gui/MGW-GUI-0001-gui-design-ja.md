# MGW-GUI-0001 共通の画面の枠

## 1. 基準の端末

- 基準：iPhone 11（画面 414 × 896 pt、縦）。試作はこの実機で触って確かめる。
- 小さい方の確認：iPhone SE（第 2・3 世代、375 × 667 pt）。E2E でも同じ大きさの端末（Playwright の「iPhone SE (3rd gen)」）で、はみ出さないことを確かめる（仕様書 v1.8。前は第 1 世代の 320 × 568 で確かめていた）。
- PC：ブラウザの窓の大きさに合わせる。

## 2. 画面の組み立て

すべての画面は、次の 3 段で組み立てる（仕様書 v1.7 で上のバーをなくし、一時停止を下のボタンの段に移した）。

```
┌───────────── 安全領域の上（ノッチ・ステータスバー） ─────────────┐
│ ┌──────────────────────────────────────────────────────────────┐ │
│ │ ゲーム画面（Canvas、論理 480 × 640。細い枠）                  │ │
│ │   HUD 帯 0–48 / UFO 48–120 / 隕石 120–580 / 発射台 580–616     │ │
│ └──────────────────────────────────────────────────────────────┘ │
│ ╭──────────────────────────────────────────────────────────────╮ │
│ │ 操作空間（論理 480 × 96、タッチ端末だけ。角の丸い枠）          │ │
│ ╰──────────────────────────────────────────────────────────────╯ │
│ [ ‖ 一時停止 ]                              [ 🔊 効果音：オン ]   │ ボタンの段（論理 480 × 64、プレイ画面だけ）
└───────────── 安全領域の下（ホームバー） ─────────────────────────┘
```

- タイトル・ランキングなど、プレイ以外の画面も、同じ枠（480 × 640 の場所）の中に出す。ランキング・クレジットは、枠の中でスクロールする。
- 操作空間は、タッチ端末（`pointer: coarse`）のときだけ出す。PC では出さない（MGW-US-0021）。PC のボタンの段は、ゲーム画面のすぐ下。
- ボタンの段は、プレイ画面のときだけ出す（MGW-GUI-0003）。

## 3. 大きさの合わせ方

- 使える広さ：画面の大きさから、安全領域（`env(safe-area-inset-*)`）と、まわりの余白（上下左右 8 pt）を引いたもの。
- 倍率：`min(使える幅 ÷ 480, 使える高さ ÷ (640 + 操作空間の 96 + ボタンの段の 64))`（PC は操作空間の 96 を足さない）。縦横比を保って拡大・縮小する（MGW-US-0005）。プレイ以外の画面でも同じ倍率を使い、画面を切り替えても枠が動かないようにする。
- ボタンの段が 48 pt より低くなるとき（小さい画面）は、段を 48 pt にし、残りの高さでゲーム画面と操作空間の倍率を決める（§5 のボタン 44 pt が段からはみ出さないように）。
- 余ったところは背景の色で埋め、ゲーム画面を左右の中央に置く。上下は上に詰める。
- Canvas の実際の画素は、倍率 × `devicePixelRatio` にし、ぼやけないようにする。
- 計算の例（仕様書 v1.7 の形。実機の値は E2E と手動で確かめる）：

| 端末 | 使える広さ（目安） | 倍率 | ゲーム画面＋操作空間＋ボタンの段 |
| :--- | :--- | :--- | :--- |
| iPhone 11・Safari | 398 × 約 698 pt | 約 0.83（幅で決まる） | 398 × 約 663 pt |
| iPhone 11・ホーム画面のアプリ | 398 × 約 798 pt | 約 0.83（幅で決まる） | 398 × 約 663 pt |
| iPhone SE・Safari | 359 × 約 578 pt | 約 0.72（高さで決まる。ボタンの段は 48） | 約 346 × 578 pt |

## 4. 安全領域とスクロール

- `<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">` とし、ゲーム画面の上とボタンの段の下に安全領域ぶんの余白を付ける（MGW-US-0022）。
- ページはスクロールさせない（`overflow: hidden`、`overscroll-behavior: none`、`body` を `position: fixed`）。
- それでもスクロールしたら（キーボードを閉じたあとなど）、すぐ 0 に戻す。iOS のホーム画面のアプリでは、ページが少しスクロールしたままだと、ボタンの押せる位置が見た目より下にずれる（試作で見つかった。§8）。
- ゲーム画面と操作空間では、拡大・長押しのメニュー・文字の選択が起きないようにする（`touch-action: none`、`-webkit-touch-callout: none`、`user-select: none`）。
- ソフトウェアキーボードを使うのは、名前の入力（MGW-GUI-0004）だけ。キーボードが出ても枠の大きさを計算し直さず、入力欄がキーボードに隠れないようにする。

## 5. 色と文字

| もの | 決め |
| :--- | :--- |
| 背景 | 黒 `#000000` |
| 文字・図形 | 白 `#FFFFFF`（擬似カラーの色は MGW-GUI-0006） |
| 選べる部品 | 白い枠の四角。押している間は白地に黒の文字 |
| ゲーム画面の文字 | 自前のビットマップフォント（8 × 8 ドットを拡大）。英数字と記号だけ |
| プレイ以外の画面の文字 | 端末の等幅フォント（`ui-monospace, Menlo, monospace`）の太字。Web フォントは使わない |
| 文字の大きさ | 本文 16 pt 以上、ボタン 18 pt 以上（ランキングの結果・日時、クレジットの役割は 14 pt 以上） |
| ボタンの大きさ | 高さ・幅とも 44 pt 以上。となりのボタンとは 8 pt 以上あける |

### 5.1 紺の画面と部品（「ブロック崩しミニ」と同じ。仕様書 v1.7）

ランキング・クレジットの画面と、プレイ画面の枠・操作空間・ボタンの段に使う。タイトル・設定・名前の入力は上の黒い画面のまま。

| もの | 決め |
| :--- | :--- |
| 背景（ランキング・クレジット） | 紺 `#0B1020` |
| 枠・パネル（操作空間・ボタン・バックアップの枠） | 背景 `#141B2E`、線 `#2E3A5C`（1 pt）、角の丸み 12 pt |
| ゲーム画面の枠 | 線 `#2E3A5C`（1 pt） |
| 文字 | `#E6EAF2`。うすい字（役割・結果・日時・案内）は `#8C96AD` |
| 目立たせる色 | 黄 `#FFD54A`（1〜3 位、自分の記録の線）。自分の記録の行の背景は `#2A2620` |
| 区切りの線（ランキングの行） | `#2E3A5C`（1 pt） |
| 文字の形 | 端末の文字（`system-ui, -apple-system, sans-serif`）。スコア・順位の数字は等幅（`ui-monospace, Menlo, monospace`） |
| 印 | ← BACK の矢印、一時停止 ‖、スピーカー、ダウンロード・アップロード、結果の ✓・✕ は、インラインの SVG で描く（Web フォント・画像のファイルは使わない） |
