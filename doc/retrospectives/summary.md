## W（わかったこと）

### うまくいったこと（くり返し効いたもの）

- **DOM・Canvas・時刻に触れない関数に分ける**（core の `step`、`overlaysFor`、`killEffectView`、`isTap`、`meteorStartPositions`、経過時間のステップ数え）。境目（0.4 秒、100 ms、10 px、180 秒）を単体テストで数えられ、E2E を減らせた（WS-0002・0007・0009・0010・0012）。
- **テスト用の入口（`?debug=1` の `__mgw`、body の data 属性、種）**。E2E が時間に頼らず決まった結果になった（WS-0002 から最後まで）。
- **PR の前のスクリーンショット**。残機のアイコン、ラジオボタン、光線の形を、手動テストの前に直せた（WS-0003・0007・0013）。
- **変更の依頼の流れ（依頼 md → 承認 → 仕様書の PR → 設計・計画の PR → TASK の PR → 手動テスト → AC の PR）**。影響の一覧の「結果」の列が、そのまま進み具合の表になった（WS-0008 から 7 回）。
- **ふりかえりの T を、次の WS の Y の最初で確かめる**。T は workflow.txt に入れてから次の WS を始めたので、同じつまずきは少なくなった（WS-0001 の「どのアプリで確かめるか」は、そのあと取り違えなかった。WS-0011 の「案の前に画面を測る」は、WS-0014 で手戻りを防いだ）。

## T（つぎにやること）

次のプロジェクトで、最初から入れる（workflow.txt の「段階ごとに先に確かめておくこと」に入れたものに加えて）。

1. **03 の試作は、本物と名前・アイコンを変えて公開する**（「GW試作」）。手動テストの案内の最初で、どのアプリで確かめるかを確かめる。
2. **E2E の端末を、画面設計の基準の端末と同じ大きさにする**（Playwright の「iPhone SE」は第 1 世代。基準が 375 × 667 なら `iPhone SE (3rd gen)`）。
3. **画面に版を出すか、その場所を 03 で決める**。版は `package.json` の `version` を埋め込む作りを、最初の土台の WS から入れておく。
4. **テスト用の入口（`?debug=1`、data 属性、種、`freeze`・`advance`）を 04 の設計に入れ、最初の WS で作る**。E2E は時間に頼らない形で始める。
5. **成果物の版を上げて sources の表記をそろえるスクリプトを、check:docs と一緒に最初から scripts/ に置く**。
6. **README と原作の表記はリリースで作る、と 00 で決めておく**（今回はそうしていたので、リリースの PR に入れられた）。
7. **Windows の PowerShell では `npm run <script> -- --flag` のフラグが届かないことがある**。フラグが要るものは `node scripts/…` で直接動かす。
8. **仕様の値（増機の点数・時間ボーナス・速さ）は、1 回の遊びで届くかを、02 で点数の幅を出して確かめる**。
