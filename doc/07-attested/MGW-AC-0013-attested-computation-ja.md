# MGW-AC-0013 タッチ操作と操作空間の確認

* **TASK**：MGW-TASK-0013（ブランチ `feat/TASK-0013-touch-input`）
* **確かめた環境**：Windows 11、Node.js v24.0.0、Playwright 1.64.1（Chromium・WebKit）

## 1. 自動テストの結果

なぞる動きは Playwright のタッチでは作れないので、指（`pointerType: touch`）のポインターイベントを送って確かめた。タップは `page.touchscreen.tap` を使った。

| 確認 ID | 確かめること | 結果 | 根拠 |
| :--- | :--- | :--- | :--- |
| MGW-TC-0021-01 | タッチ端末では、フィールドの下に高さ 96 の操作空間が出る | OK（3 つの project） | `✓` › e2e\touch.spec.ts › MGW-TC-0021-01。iPhone 11・iPhone SE では、ゲーム画面のすぐ下に同じ幅・同じ位置で、高さがゲーム画面の 96/640 の操作空間が出て、「なぞって移動 ・ タップで発射」と書いてある。PC では出ない |
| MGW-TC-0021-02 | 操作空間かプレイ空間をなぞると、発射台（発射後はミサイル）が指の x を追う | OK（iphone11-webkit・iphonese-webkit） | 同じく MGW-TC-0021-02。操作空間とゲーム画面のそれぞれで、発射台が x 100・400 を追い、発射後はミサイルが x 160 を追う。前提（発射前・発射台が真ん中）を先に確かめた |
| MGW-TC-0021-03 | 操作空間かプレイ空間をタップすると発射する | OK（同上） | 同じく MGW-TC-0021-03。操作空間とゲーム画面のそれぞれで、タップすると playing になる |
| MGW-TC-0021-04 | 指を触れ続けている間は、加速噴射になる | OK（同上） | 同じく MGW-TC-0021-04。発射後に触れている間は `isBoosting` が true、離すと false |

E2E の合計：`67 passed`、`11 skipped`（PC は 0021-02〜04 を飛ばす）。`npm run verify`（単体テスト `58 passed`）も通った。

画面：iPhone 11・iPhone SE の幅（WebKit）で、プレイ画面と操作空間が 1 画面に収まり、操作空間の文字と矢印が見えることを確かめた。

## 2. 手動の確認（WS-0004 の終わり、2026-10-27、オーナー、iPhone 11）

| 確認 ID | 確かめること | 結果 |
| :--- | :--- | :--- |
| MGW-TC-0021-05 | 操作空間で操作するとき、指でミサイル・UFO・光線が隠れない | OK（ホーム画面の本物の「GWミニ」。操作空間でなぞる・離して発射・押し続けて噴射を行い、指で隠れなかった） |

- 虫めがねを止める直し（PR #33）のあとも、タップで発射・なぞって移動・押し続けて噴射が、これまでどおり動いた。

## 3. 設計と違う作りにしたこと

- 操作空間は、タッチ端末ではどの画面でも場所を空けておき、中身（文字・矢印・上の線）はプレイ中だけ出す。画面を切り替えても、ゲーム画面の大きさが変わらないようにするため。
- 入力は、ゲーム画面と操作空間のどちらを触っても、ゲーム画面の左右を基準に x を決める（操作空間はゲーム画面と同じ幅・同じ位置に置く）。
- `setPointerCapture` が使えないときも、枠の中では動くようにした。
- 大きさの E2E（MGW-TC-0005-01）を、タッチ端末では操作空間の分を含めて確かめるように直した。

## 4. 確認できなかったこと

- 本当の指でなぞったときの動きは、E2E ではポインターイベントを送って代わりに確かめた。§2 の手動で、実機で触って見る。
- Android の端末では確かめていない（実機がない。MGW-TST-0001 §6.1）。
